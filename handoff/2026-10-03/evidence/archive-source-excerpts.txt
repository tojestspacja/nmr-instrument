L32: ## How a real scan runs
L33: 
L34: The pulse program runs on the ESP32. `runOneScan()` in `Sequencer.cpp` does this for each scan:
L35: 
L36: 1. optional pre-polarization (`polarize_ms`, then `t_polarize_settle_ms`);
L37: 2. sets this scan's pulse phase;
L38: 3. blanks the receiver, then holds `TX_EN` high for the 90° pulse (`t90_us`); in echo mode it waits
L39:    `tau_us` and gives the 180° pulse;
L40: 4. waits out the dead time (`t_dead_us`), while the coil is still ringing, then releases `RX_BLANK`;
L41: 5. starts the ADC burst at `t_acq_start_us` after the pulse and records for `t_acq_ms`.
L42: 
L43: The scan set repeats this `n_avg` times, `t_repeat_ms` apart, and cycles the pulse phase between
L44: scans (CYCLOPS) when `cyclops` is on. The default values of these settings are in `NMR-FIRMWARE.md` at
L45: the reference commit; they are deliberately not copied here, so they cannot go stale.
L46: 
L47: Note that class-board-2026's own guidance (`CLAUDE.md`, "Real-hardware code is unverified until
L48: measured") treats the real-hardware branch of this code as a hypothesis until `hardware/docs/bring-up.md`
L49: says otherwise; only its SIM mode has run.

L51: ## Three interfaces, three jobs
L52: 
L53: ```text
L54: Course showcase card ──────────► "What is this project?"   (one card, links here)
L55: 
L56: Public browser (GitHub Pages)
L57:    └─► this site + /simulator/  ──► "How is it built, how does it work?"   simulation only
L58: 
L59: Phone or laptop on the local Wi-Fi
L60:    └─► instrument-XXXX.local    ──► "Operate the real instrument"
L61:           └─► ESP32 ─► TX / RX / ADC hardware
L62: ```
L63: 
L64: The public site cannot drive the board: it is served over HTTPS from the internet, and the
L65: instrument is a plain `ws://` device on your local network. Real scans are started from
L66: `instrument-XXXX.local` → **NMR** → **Apply settings** → **Start** (or **Pulse** for a single test
L67: pulse), or from a laptop with `instrument nmr --n-avg 8 --csv fid.csv`.
